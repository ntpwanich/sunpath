# ผู้เข้าชมทุกคนใช้ข้อมูลชุดเดียวกัน และไม่มีระบบบัญชีผู้ใช้

SunPath ต้องเปิดจากลิงก์แล้วใช้งานได้ทันทีโดยไม่ต้องสมัครสมาชิก ผู้เข้าชมกดเลือกว่าจะเข้าใช้ในฐานะบทบาทใดจากหน้าเข้าสู่ระบบ เราเก็บเพียง `userId` ที่เขาเลือกไว้ใน cookie ที่เซ็นกำกับ ไม่มีรหัสผ่าน ไม่มี session store และไม่ดึงไลบรารี auth เข้ามาเลย สิทธิ์ตรวจที่ระดับ role ตรง ๆ จากค่าใน cookie นั้น

**ผลที่ตามมาซึ่งตั้งใจ:** ผู้เข้าชมสองคนที่เลือกบทบาทเดียวกันในเวลาเดียวกันจะแก้ข้อมูลชุดเดียวกันและเห็นการแก้ของกันและกัน เรารับผลนี้เพราะทางเลือกอีกทางคือให้ผู้เข้าชมแต่ละคนได้ข้อมูลของตัวเอง ซึ่งบังคับให้ทุกตารางต้องมีคอลัมน์ระบุเจ้าของชุดข้อมูล ทำให้ unique constraint ทุกตัวกลายเป็น composite และทำให้กติกาการจับข้อมูลซ้ำด้วยเบอร์โทรซับซ้อนขึ้นทันที — ต้นทุนถาวรที่จ่ายไปเพื่อแก้สถานการณ์ที่งาน portfolio แทบไม่เจอ และการสร้างข้อมูลใหม่ทุกคืนตาม [ADR 0002](./0002-vercel-neon-with-nightly-reseed.md) ก็ล้างความเละที่สะสมระหว่างวันให้อยู่แล้ว

การไม่มีบัญชีผู้ใช้ยังทำให้ระบบนี้ย้ายไปใช้งานจริงไม่ได้ทันทีโดยไม่เติม auth เข้าไปก่อน ซึ่งเป็นการแลกที่ยอมรับได้ เพราะสิ่งที่งานชิ้นนี้ตั้งใจแสดงคือความเข้าใจกระบวนการขายของผู้รับเหมาโซลาร์ ไม่ใช่การต่อ identity provider
