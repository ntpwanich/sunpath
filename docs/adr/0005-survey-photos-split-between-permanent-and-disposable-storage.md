# แยกรูปถ่ายผลสำรวจเป็นของถาวรกับของใช้แล้วทิ้ง

รูปถ่ายจาก Survey Report เก็บบน Vercel Blob แยกเป็นสอง prefix — รูปที่มากับข้อมูลตัวอย่างอยู่ถาวรและไม่ถูกแตะต้อง ส่วนรูปที่ผู้เข้าชมอัปโหลดจากหน้ากรอกผลสำรวจถูกล้างทั้ง prefix ทุกคืนพร้อมกับการสร้างข้อมูลใหม่ตาม [ADR 0002](./0002-vercel-neon-with-nightly-reseed.md)

**ปัญหาที่วิธีนี้แก้:** ไฟล์ไม่ได้อยู่ในฐานข้อมูล การล้างและสร้างฐานข้อมูลใหม่จึงลบแถวที่อ้างถึงรูปทิ้ง แต่ไม่ลบตัวรูป ถ้าปล่อยไว้ รูปที่ผู้เข้าชมอัปโหลดจะกลายเป็นขยะที่ไม่มีใครอ้างถึงและสะสมไปเรื่อย ๆ จนเต็มโควตา 1 GB ของแผน Hobby ขณะเดียวกันรูปของข้อมูลตัวอย่างต้องรอดข้ามการรีเซ็ต ไม่อย่างนั้นผลสำรวจทั้ง 180 รายการจะไม่มีรูปประกอบตั้งแต่คืนแรก ซึ่งทำลายความน่าเชื่อของข้อมูลที่ทั้งชุดนี้พึ่งพา

**ทางเลือกที่ปฏิเสธ:** เก็บรูปเป็น bytea ในฐานข้อมูล — ได้ความสอดคล้องแบบสมบูรณ์เพราะรีเซ็ตทีเดียวจบ แต่ Neon แผนฟรีให้ 0.5 GB ต่อโปรเจกต์ ขณะที่รูปจากมือถือใบละ 2-4 MB คูณกับข้อมูลตัวอย่าง 180 รายการก็เกินโควตาไปแล้วก่อนที่ผู้เข้าชมคนแรกจะอัปโหลดอะไร
ไล่ลบเฉพาะไฟล์ที่ไม่มีแถวอ้างถึง — ถูกต้องกว่าในทางทฤษฎี แต่ต้องอ่านรายการไฟล์ทั้งหมดมาเทียบกับฐานข้อมูลทุกคืน ซึ่งซับซ้อนและพังเงียบได้ ขณะที่การล้างทั้ง prefix เป็นคำสั่งเดียวที่ถูกเสมอ
ไม่เก็บจริงแล้วให้หน้ากรอกผลสำรวจชี้ไปยังรูปตัวอย่างที่มีอยู่แล้ว — ง่ายที่สุด แต่ทำให้ข้อกำหนดที่ว่าหน้ากรอกผลสำรวจต้องใช้งานได้จริงบนมือถือกลายเป็นคำกล่าวอ้างที่พิสูจน์ไม่ได้

**ผลที่ตามมา:** ชั้น domain เห็นที่เก็บไฟล์ผ่าน interface เท่านั้น เพราะ Vercel Blob ไม่มีตัวจำลองสำหรับรันในเครื่อง integration test จึงใช้ตัวปลอมที่เก็บในหน่วยความจำแทน
